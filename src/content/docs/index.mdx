:::caution[Read this first]
Kaleidoscope is **implementation in progress**, not a finished product. The
storage engines are durable; several integration components are still v0
(in-memory, lose data on restart); a number of capabilities are roadmap. This
site is honest about that on every page. Start with
[Is it ready for you?](/start/status/) before you plan an adoption.
:::

## What you get

<CardGrid>
  <Card title="One tool, four signals" icon="puzzle">
    Logs, metrics, traces and profiles through a single platform built around
    the OpenTelemetry wire formats and semantic conventions. No four-stack
    integration project.
  </Card>
  <Card title="OpenTelemetry at every seam" icon="random">
    Applications emit OTLP. Every internal contract is an OpenTelemetry-defined
    format. If it speaks OTLP, it speaks to Kaleidoscope.
  </Card>
  <Card title="Built from scratch, on FOSS libraries" icon="setting">
    First-party engines on Apache Arrow, Parquet, DataFusion and Tokio. Not a
    re-skin of Loki, Mimir, Tempo or Grafana.
  </Card>
  <Card title="Structurally un-rug-pullable" icon="approve-check">
    AGPL-3.0 platform, Apache-2.0 SDKs, contributions under the DCO with no CLA,
    ever. Designed so no single party can re-license it later.
  </Card>
</CardGrid>

## The cost thesis, in one line

The big vendors charge for rich instrumentation, high-cardinality metrics, long
retention and broad team access — the very practices they tell you to adopt.
Kaleidoscope removes the margin: you pay for the compute and storage underneath,
not for a per-host, per-GB, per-cardinality, per-seat bill on top. See
[Why it exists](/start/why/).
